Knesset 2026: a decision-model forecast

Two decision models, Clef and Jev 1.14, answered 39 probability questions about Israel's 27 October 2026 election. Both read the same frozen evidence pack: the outgoing Knesset, the candidate lists, every poll since September and a news digest. Each answered twice, without and with Kalshi and Polymarket prices in the pack. No LLMs were involved.

Some quantities were asked twice in different forms, for example "Will Yashar be the largest list?" as yes/no and as a pick from the lists. A coherent model gives the same number both times. The table shows the gap between the two answers.

Decision models take a block of evidence (the state) and typed questions (yes/no, one-of-N, ordered bins), and return probabilities. They are called through OpenRouter's /api/v1/systemone endpoint and billed only for input tokens. Every question in a request shares one billing of the state.

Clef's cheapest OpenRouter host silently truncates the state to 16,384 tokens, so this run pinned Clef to DeepInfra (64k context). The runner rejects any response billed at a context cap.

Every question's resolution rule was fixed before the run. Once the Central Elections Committee certifies the result (around 5 November 2026), each answer gets a Brier score, and so do the market prices.
